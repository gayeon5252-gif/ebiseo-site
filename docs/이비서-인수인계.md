## 1. 서비스 개요

**이비서(ebiseo)** — 한국 이사 준비 전 과정을 돕는 무료 모바일 대응 웹서비스.

- 슬로건: 집을 구하는 순간부터 이사 후 정리까지, 놓치는 일 없게
- 운영 주소: https://isabiseo.com (www도 동일하게 연결됨)
- 사업 목표: 트래픽을 모아 쿠팡파트너스 수수료 + 애드센스 광고 수익

**기술 구성**

- 정적 사이트 (HTML/CSS/순수 JavaScript, 빌드 과정 없음)
- 호스팅: **Cloudflare Pages** (프로젝트명 `ebiseo`) — zip 드래그앤드롭 배포
- 로그인/DB: Supabase (구글·카카오 로그인 모두 작동)
- 분석: Google Analytics 4
- 서버·백엔드 코드 없음. 모든 계산은 브라우저에서 실행됨.

**`_redirects`에 규칙을 다시 넣지 마세요.** Cloudflare Pages는 확장자 없는 주소를 기본으로 처리합니다. Netlify 시절의 `/situation → situation.html` 같은 규칙을 넣으면 **리다이렉트 무한루프가 나서 페이지가 안 열립니다.** 실제로 이전 중에 이 문제가 발생했습니다.

**Cloudflare Pages는 `.html` 주소를 308로 되돌립니다.** `/foo.html`을 요청하면 확장자를 뗀 `/foo`로 리다이렉트합니다. 그래서 **검색엔진 소유확인을 "HTML 파일 업로드" 방식으로 하면 실패할 수 있습니다.** 검증기가 `.html` 주소에서 곧바로 200을 기대하기 때문입니다.

- 소유확인은 **메타태그 방식**을 쓰세요. `index.html`의 `<head>`에 `<meta name="naver-site-verification" ...>`이 이미 들어 있습니다 (2026-08-16 라이브 확인).
- 사이트에 있는 `naver*.html` / `google*.html` 인증 파일은 남겨두되, 소유확인 수단으로 의존하지 마세요.

| 번호 | 하는 일 |

| 3 | **캐시 버전 올리기** — 모든 HTML의 `?v=N`을 N+1로 일괄 변경. **CSS·JS를 고쳤을 때만** 실행 |
| 4 | **라이브 사이트 점검** — 배포 후 실행. 캐시 버전·사이트맵 개수·가이드 글 수가 내 폴더와 일치하는지, 사이트맵의 모든 주소가 실제로 열리는지 확인 |

## 5. 배포 방법 (Cloudflare Pages)

1. 소스를 수정한다
2. zip으로 압축한다 — **`.md` 파일, `ads.txt`, `_redirects`, `_redirects.netlify-backup.txt`, `netlify.toml`, 기존 zip은 제외**
   - 프로젝트 폴더에 `zi1lngZz`처럼 **확장자 없는 옛 zip 파일**이 섞여 있습니다. 이것도 빼세요.
3. https://dash.cloudflare.com → Workers & Pages → `ebiseo` → **Create deployment**
4. Production 선택 → **file**을 눌러 zip 선택 → **Save and deploy**

**알아두실 점**

- zip 안의 경로 구분자는 **정슬래시(`guide/...`)여야 합니다.** PowerShell의 `Compress-Archive`는 역슬래시(`guide\...`)로 넣어서 폴더가 안 풀릴 수 있습니다. 윈도우 탐색기의 "압축(ZIP) 폴더"로 만들거나, 만든 뒤 내부 경로를 확인하세요.
- Cloudflare 무료 플랜은 **배포 월 500회, 대역폭 과금 없음**. 트래픽이 늘어도 사이트가 멈추지 않습니다.
- JS를 고치면 모든 HTML의 `?v=10`을 `?v=11` 등으로 올리는 것이 안전합니다 (46개 파일 일괄 치환).
- `_headers`가 js·css를 `max-age=0, must-revalidate`로 두어 변경이 즉시 반영됩니다.
- 배포 후 확인할 때는 Ctrl+F5로 강력 새로고침.
- 도메인을 갓 옮긴 직후에는 브라우저가 옛 IP를 기억해 옛 사이트가 보일 수 있습니다. `chrome://net-internals/#dns` → Clear host cache.

**Netlify는 더 이상 사용하지 않습니다.** 무료 300 크레딧 / 배포 1회 15 크레딧 / 대역폭 1GB당 20 크레딧 구조라, 트래픽이 늘면 사이트가 멈춥니다. 2026-08-10 기준 잔여 14 크레딧으로 사실상 소진 상태였고 이것이 이전 사유였습니다. 기존 Netlify 프로젝트는 방치해도 무방하며 지워도 됩니다.

## 6. 로그인 (Supabase)

**구글·카카오 모두 정상 작동합니다.** (2026-08-10 확인, 실제 카카오 가입 회원 존재)

카카오 설정에서 반드시 알아야 할 것:

- Supabase는 카카오에 **항상 `account_email profile_image profile_nickname` 세 가지를 요청**합니다. 앱 코드에서 `scopes`를 지정해도 빠지지 않고 뒤에 덧붙기만 합니다.
- 따라서 카카오 개발자센터 [카카오 로그인 > 동의항목]에서 **이 세 항목이 모두 '사용 안 함'이 아니어야** 합니다. 하나라도 빠지면 `KOE205` 오류가 납니다.
- 현재 설정: 닉네임 **필수 동의** / 프로필 사진 **선택 동의** / 카카오계정(이메일) **필수 동의 [수집]**
- 이메일 항목은 **비즈 앱에서만** 설정 가능합니다. 개인 개발자 본인인증으로 전환 완료된 상태입니다.

**계정 중복 처리:** Supabase는 같은 이메일이면 다른 소셜 수단으로 로그인해도 **자동으로 한 계정에 연결**합니다. 그래서 구글로 가입한 사람이 카카오를 눌러도 계정이 두 개로 나뉘지 않습니다. 카카오 이메일을 '필수 동의 [수집]'으로 둔 이유가 이것입니다 — 이메일 없는 계정이 생기면 합칠 방법이 없습니다. 마이페이지에 연결된 로그인 수단이 배지로 표시됩니다.

## 10. 작업할 때 지켜온 원칙

1. **없는 것을 있는 척하지 않는다.** 가짜 업체·리뷰·제휴, 미작동 기능을 실제처럼 표시하지 않습니다. 링크가 비면 블록이 사라지도록 만든 것도 이 원칙 때문입니다.
2. **비밀키는 프런트엔드에 넣지 않는다.** service_role 키는 절대 금지.
3. **정보에는 기준일과 출처를 붙인다.** 비용·금리·법령은 "참고용이며 법률·금융 자문이 아님"을 명시. 공공기관 페이지도 갱신이 늦는 경우가 많으니 확인한 날짜를 반드시 남깁니다.
4. **확인 못 한 것은 "확인 필요"로 표기한다.** 추측한 수치를 적지 않습니다.
5. **Cloudflare Pages 프로젝트는 `ebiseo` 하나만 쓴다.** 새로 만들지 않습니다.
6. **실제로 배포하지 않았으면 배포했다고 말하지 않는다.**
7. **작업은 단계별로 나누고, 중간에 확인을 받는다.**
8. **전통 민속(길일·사주)은 예측이 아니라 참고용으로 표기한다.**
9. **개인 메일 주소를 사이트에 노출하지 않는다.**
