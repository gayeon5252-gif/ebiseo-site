# 이비서 서버 자동 관리

이 작업은 GitHub 서버에서 실행되므로 운영자 PC가 꺼져 있어도 실행된다.
공개 저장소의 표준 Ubuntu 실행기를 사용하며 AI API, 유료 광고, 유료 실행기를 호출하지 않는다.

## 실행

- 매일 한국 시간 09:17 전후. GitHub 예약 작업은 지연될 수 있다.
- main의 사이트·운영 코드 변경 시, 또는 Actions에서 수동 실행 시.
- 기존 가이드의 제목·설명·기록된 날짜로 `public/guide-feed.xml`을 갱신한다.
- 가이드가 사이트맵에서 누락된 경우에만 해당 주소를 추가한다. 기존 주소나 날짜를 임의로 고치지 않는다.
- 실제 변경이 있을 때만 생성 파일을 main에 커밋한다. 기존 Cloudflare Pages 자동 배포 경로를 사용한다.
- RSS와 사이트맵의 라이브 본문이 생성 결과와 일치하는지 최대 3분간 확인한다. 계속 불일치하면 실패로 처리한다.
- 홈·핵심 도구·사이트맵 전체 주소·robots를 점검하며 결과를 Actions 실행 요약에 남긴다.
- 매월 첫 정상 점검 결과를 `monthly/YYYY-MM.json`에 한 번 보존한다. 매일 불필요한 커밋은 만들지 않는다.

## 확인 범위

HTTP 응답과 정적 HTML만 검사한다. 오류가 나면 해당 실행은 실패 상태가 된다.
GA4 실수집·제휴 정산·날짜 입력의 JavaScript 동작은 이 검사 결과만으로 정상이라고 판정하지 않는다.
RSS 요약은 기존 글의 meta description을 사용한다. AI가 새 글을 쓰거나 법·정책 내용을 자동 수정하는 기능은 연결하지 않았다.
Threads 및 블로그 계정에 게시하는 기능도 이 워크플로에는 없다. 해당 플랫폼의 예약 발행과 구분한다.

## 운영과 중지

[GitHub Actions](https://github.com/gayeon5252-gif/ebiseo-site/actions/workflows/ebiseo-operations.yml)에서 실행 결과 확인, 수동 실행, 작업 비활성화가 가능하다.
실패 통지는 GitHub 계정의 Actions 알림 설정에 따른다. 별도 이메일 발송 시스템은 설치하지 않았다.
변경 롤백은 생성 파일 또는 운영 설정을 담은 커밋을 되돌리는 방식으로 한다.
권한 철회, 저장소 비공개 전환, 서비스 정책 변경, 반복 실행 실패는 별도 점검이 필요하다.
GitHub는 공개 저장소 활동이 60일 없으면 예약을 중단할 수 있다. 정상 운영 중에는 실제 월별 점검 기록이 저장되지만, 장기 실패 시 실행 상태를 확인해야 한다.
